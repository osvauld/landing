# Osvauld

Osvauld is an experimental runtime that makes it easy to develop collaborative apps, graphics and workflows, including ones your AI writes for you. Apps are small Lua programs over synchronized documents, rendered natively and written or changed by people and agents while they run. Collaboration, persistence and identity come with the platform, so an app is just its own logic.

Status: experimental. Every demo on the website is a real recording from the shell, produced by script rather than a screen recorder. The source is on GitHub and the documentation describes the architecture.

# What it can do so far

- Apps: an app is a Lua file. The runtime turns a description of the interface into layout and vector pixels every frame. Documents persist and sync with no extra code in the app.
- Workspaces: the home screen is a Lua file in your encrypted store, so the workspace itself is configurable. A broken edit is refused and the workspace keeps running; Reset restores the original.
- Sync: persistence and collaboration come with the document, not the app. Each person has their own identity and node, and edits merge on reconnect.
- Agents: agents drive the shell over a local bridge. They read a source file and send exact edits, and the running app reloads. The agent changes code, not pixels.
- Files: workspace assets are edited in place, in apps written in Lua inside the same shell.
- Physics: a 2D physics engine (gravity, wells, forces, joints, a grabbing hand) driven from Lua.
- Vectors and data: diagrams, node graphs, charts and meshes drawn natively that respond to the pointer, with no webview.
- Determinism: the shell runs windowless on a virtual clock that only moves when asked, so layout and time-dependent behaviour are exact and recordings are reproducible frame for frame.
